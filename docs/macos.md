# macOS 客户端

0.3.0 将 macOS 加入本机项目执行端，继续复用 Electron + React 界面、WSS 连接和 Linux 上的官方 Claude Code。当前为内测实现，正式签名、公证、实际更新和完整权限矩阵仍待验收。最低系统版本为 macOS 13，分别构建 arm64 与 x64。

## 本机运行

开发环境需要 Node.js 24、npm，以及系统 zsh 或 bash、OpenSSH 客户端和 `/usr/libexec/sftp-server`。不需要开启系统“远程登录”、安装 sshd 服务或放行本机入站端口。

```sh
npm ci
npm run setup:desktop
npm run build
npm run desktop
```

源码入口提供“本地模拟”和“远程代理”。模拟模式不访问真实 Claude；远程模式填写自己可信的 Linux 服务地址、证书指纹和服务凭据。

项目选择后，客户端先用文件系统操作保留路径及父目录的准确错误，再经本次连接的实际 SSH 身份检测目录读取、SFTP 列目录、独占创建和写入测试文件并清理。失败结果保留操作阶段、错误来源和底层错误码，分别提示访问拒绝、操作受限、只读磁盘、空间或配额不足、连接故障；SFTP 通用失败保留为原因未明。清理失败不会覆盖原始错误，遗留检测目录会单独显示。

macOS 受保护位置的访问拒绝会提供“打开文件与文件夹设置”入口，并明确隐私授权只是可能原因；无法打开时显示手动设置路径。普通目录权限、ACL、文件锁定及只读磁盘需分别处理，不将 `EACCES` / `EPERM` 或 SFTP 权限拒绝直接等同于缺少完整磁盘访问。Apple 对文件访问授权的范围见[官方说明](https://support.apple.com/en-ca/guide/security/secddd1d86a6/web)。

本机原生会话的失败文件工具，以及报告明确文件访问错误的命令工具，在展开输出后提供“检测项目访问”。有结构化目标文件路径时，检测还经 SFTP 读取目标元数据，并检查本机文件及父目录访问权限，不打开、截断或写入已有文件；未能识别具体路径的命令只检查项目根目录。根目录基础通道检测通过不保证每个已有文件都可修改，目标元数据检测也不能保证实际修改成功。恢复后保持诊断结果，由用户核对已发生的改动并决定是否重试，不重放文件修改。会话工具诊断在切换会话或连接后会丢弃迟到结果，其他设备历史不能触发本机诊断。

“设置 → 常规 → 重新检测开发环境”在没有运行任务时重新连接，读取新的登录 shell 环境。Homebrew、nvm/fnm/asdf 等工具是否可用取决于用户的登录启动脚本；启动脚本交互等待或超量输出会明确失败，不在每条命令上重复执行初始化。SSH agent 和环境变量留在本机，服务端只收到平台、shell 路径与定时任务文件路径。

## 执行与资源生命周期

每次连接生成独立主机密钥和登录密钥，只监听 `127.0.0.1` 动态端口，验证公钥认证签名。SSH 支持非交互 exec、stdin/stdout/stderr、退出状态、并发通道、保活和系统 SFTP；现代 OpenSSH `scp` 使用 SFTP。交互式 shell、PTY、端口转发和未知子系统被拒绝。客户端已有的原生终端仍位于 Linux 服务端。

SSH 服务运行在受 IPC 监督的应用子进程。每条命令和 SFTP 子系统有独立受管进程组；通道结束、连接断开、主动退出和主进程崩溃统一请求终止，限期后强制终止剩余受管成员。主动 daemonize、另建会话或脱离进程组的程序不在完整回收保证内。进程组的信号 0 探测返回 EPERM 时表示不能通过该探测确认可发信号，监督器继续持有该组并走既有的限期终止和回收路径；真实终止信号的权限失败不会被当成组已消失。

`ssh-channel-output.mjs` 为已固定的 `ssh2 1.17.0` 修正 stdout/stderr 共享发送窗口的待写生命周期，避免窗口耗尽后旧回调阻塞错误流。该适配器集中使用依赖的内部字段，限制版本并由真实 SSH 窗口耗尽、并发大输出和通道关闭回归保护；升级 ssh2 前必须重新审查这一适配层，不能只修改版本号。

开发服务器、watcher 等长任务需要保持对应 SSH 命令存活，例如由 Claude 的后台 Bash 任务托管。关闭窗口默认只隐藏，连接仍在；点击 Dock 或菜单栏图标恢复，显式“退出”才结束连接。休眠恢复会关闭旧连接并要求重新连接，不自动重放结果未知的命令。定时任务维持既有“晚于计划 10 分钟跳过”的规则，不保证系统休眠时准点运行。

## 设备与路径

安装 ID 是随机 UUID，保存在本机设置中，不采集硬件标识。会话的项目路径属于创建它的执行设备。其他设备的会话可查看和导出历史，运行或打开原生终端前必须通过“选择本机文件夹”明确重新绑定。查看其他设备历史不会读取本机同路径的 Git 分支，删除历史也不清理本机同名工作目录。

历史记录默认 Windows，Mac 不会自动认领。历史 Windows 提示模板在压缩前保持稳定；项目、平台、shell 和定时任务位置变化随下一条普通输入提醒，收到原生确认后才记录已交付。

Windows 路径保留大小写不敏感比较；POSIX 路径不统一转小写或替换反斜杠。本机以文件系统设备号和 inode 合并符号链接与实际大小写别名，界面显示目录路径。旧显示名称、置顶与折叠键仅在对应关系明确时迁移。普通会话目录清理仅删除应用管理范围内仍为空的目录，拒绝符号链接指向外部目录。

## 协议 15 与数据迁移

0.3.0 在 0.2.11 的多设备与连接复用上扩展平台执行描述，协议统一为 15。认证首帧保留版本号、服务凭据、设备名称及通道请求；设备 ID、平台和架构随后独立登记，SSH 就绪时提交执行描述。服务端拒绝在同一连接中更换设备身份，也检查执行描述与登记的 ID、平台和架构一致。安装包信息在设备登记后按平台更新，避免 Mac 使用默认 Windows 安装包。旧协议仍可得到可读的版本不一致提示。

升级前备份服务端的数据目录（SQLite、原生会话和配置）与客户端配置，结束运行和原生终端，再把服务端与客户端配对升级。协议 13 / 14 与 15 不共同执行任务；升级不自动重发问答、审批或文件操作。若需回退，恢复配对的旧程序和升级前数据备份，不让旧程序直接写入已迁移的数据。

服务端第一次启动在事务内规范化会话 metadata，并记录一次迁移标记；不会创建或重放工具事件：

- 0.2.10 及更早无归属会话仍按 Windows 路径处理，只能由首次使用它的 Windows 设备认领；Mac 必须先明确选择本机项目并迁移或分叉。
- 0.2.11 的 `device: { id, name }` 保留原归属；同名路径不会把另一台设备当成本机。
- macOS 内测的 `deviceId` 转为统一的 `device.id`，保留项目平台和执行环境。冲突的双重身份会拒绝读取，不能静默选一方。
- 0.2.11 的环境变量提示模板与早期 Windows 模板在原生压缩前保持稳定；项目、设备、shell 或定时任务位置变化随下一条普通输入提醒，只有原生确认收到后才标记为已交付。原生 slash 命令不会消费待交付提醒。

客户端继续使用原配置中的设备 ID，登录与本机检测共享同一次身份读取。不要手动删除设备 ID 来解决绑定问题；在界面选择本机项目完成显式迁移。系统凭据存储和签名更新的跨版本延续仍需正式安装包验收。

## 构建安装包

本机内测允许显式未签名构建：

```sh
npm run package:macos -- --unsigned --dir
# 生成 DMG / ZIP 内测资产：
npm run package:macos -- --unsigned --arm64
```

arm64 应用目录为 `artifacts/macos/mac-arm64/CC Desk Tunnel.app`，x64 为 `artifacts/macos/mac/CC Desk Tunnel.app`。打包包含 Electron 与 SSH 的纯 JavaScript 运行依赖；实际 SSH 子进程使用随包 Electron 的 Node 模式，不依赖开发 Node 或开发仓库。

正式构建不加 `--unsigned`，需要 Developer ID Application 签名身份以及完整公证配置：钥匙串 profile、Apple ID 应用专用密码配置或 App Store Connect API key 配置。凭据通过环境和系统钥匙串提供，不写入仓库。固定 Bundle ID 为 `io.github.ccdesktunnel.desktop`，启用 Hardened Runtime，构建执行公证、staple 验证和 Gatekeeper 检查。

```sh
npm run package:macos -- --arm64
npm run package:macos -- --x64
```

应用原生架构构建会执行离线包回归，覆盖实际应用启动与 SSH worker。交叉构建不等于目标硬件验收；正式发行还需要 Intel Mac 的本机测试。

## 更新与发布

服务端按平台与架构选择安装包，分别保留最近三个版本，Mac ZIP 优先用于自动更新，DMG 用于首次或手动安装。客户端沿用连接使用的服务认证、证书指纹和系统代理下载，校验字节数与 SHA256，失败不安装。每次更新固定所属连接与发布资产快照；换连接、退出和超时会取消未完成下载并清理私有临时文件。TCP、TLS 握手与 HTTP 响应都受截止时间和取消控制。

Mac ZIP 通过带随机令牌、仅监听回环地址的临时更新源交给 Electron 内置 Squirrel.Mac；服务凭据不交给更新框架，应用签名由系统更新框架验证。运行中禁止安装；未签名内测包不支持自动更新。DMG 只打开供用户完成手动安装。原生检查超时或取消后，客户端会等待其真实结束，避免把迟到结果交给另一轮更新。取消即时安装不能撤销 Squirrel 已缓存的更新，它可能在下次启动时应用。原生安装派发失败会保留错误反馈，窗口已关闭时提示重新启动。自动更新签名要求见 [Electron 官方文档](https://www.electronjs.org/docs/latest/api/auto-updater)。

正式发布先在各平台分别构建，再集中组合资产。稳定版要求 Windows x64、Mac arm64、Mac x64 的完整且已验收产物，Mac 必须同时具备 ZIP 与 DMG 以及签名、公证、目标架构启动回归记录。Mac 和 Windows 的构建记录必须来自同一干净 Git 提交；发布前重新核对实际组装文件的大小与哈希，以及服务端源码身份。预发布允许有限平台资产，不能当作全部平台验收完成。

```sh
npm run release -- --dry-run --client-assets=artifacts/windows --client-assets=artifacts/macos
```

`release.json` 与 `SHA256SUMS` 记录版本、协议版本、平台、架构、格式、大小和哈希。未签名内测包不进入正式发布。应用内更新的签名身份、Keychain 授权延续和配置保留必须用正式安装包验证。

## 验证与待验收

```sh
npm run typecheck
npm run format:check
npm test
npm run test:ui
git diff --check
```

本机自动测试覆盖协议、设备隔离、历史迁移、提示提醒确认、实际 SSH/SFTP/scp、并发和大输出、WSS/代理/证书指纹、通道断开与进程回收、路径与目录清理、Command 与原生菜单、Electron 隔离和未签名包启动。UI 模拟服务与真实 Claude 是不同验证层。

尚未验证：正式 Developer ID 与公证产物、Finder 启动下 TCC 拒绝/恢复/撤销、Keychain 更新连续性、实际签名更新安装、真实 Linux 服务与 Claude 工作流、Intel 硬件、最低系统版本、大小写敏感和外部卷、Windows 发行安装回归。首次生产升级前备份服务端 SQLite、原生存储与客户端配置，两端配对升级；回退时按同一兼容版本恢复，必要时使用迁移前备份。
